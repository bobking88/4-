## 4. 方案与最小需求

**建议后续采用一次固定版本命名空间适配，而不是通用可配置执行器。** 这是作者建议，尚未获用户选定或实施批准。

备选的通用命名空间接口会扩大路径与权限校验面，不是当前恢复一次受控验收所必需。复用旧目录、改旧协议、用新 worktree/根目录别名绕过独占检查，或关闭身份校验，均不可采用。

后续规格应只涵盖：

1. 在 driver 中让固定协议名、输出根、case/packet 前缀、本地协议路径及远端登记路径一致指向一个新的固定版本；保持根目录、继承句柄、nonce、协议摘要与登记提交校验。
2. 同步 driver 测试中固定命名空间的既有夹具和明确过时的路径预期，保留原有行为断言；覆盖旧协议/混合路径/身份变化/已存在新目录的拒绝条件。当前没有增加或运行这些测试。
3. 在原合成验收器中设定新的固定证据与 scratch 位置，不复用已完成的合成目录；保持历史来源保护、原生接口模拟守卫和失败原件保存。当前没有修改验收器。
4. 开发完成并经另行批准的复查后，才生成新的46项源码身份和新协议；保留原始哈希与 Git 规范化内容的两种验证，不能把本轮核对授权填成原生运行授权。

预期最小代码/测试触及范围是原 driver、driver 测试及原合成验收器三个文件；这不是允许现在修改它们的白名单。发现范围扩大时应先说明原因，不能顺带重构执行系统。
