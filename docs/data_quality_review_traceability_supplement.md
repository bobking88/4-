# 数据质量复核可追溯性补录说明

## 适用范围

本说明对应 `数据集/dataset_review_20260727/review_queue.csv` 的分层抽检队列。该队列共 823 张公开矿物标本图像，包含既有的人工复核结论，不对任何图像的 `review_decision` 作自动改写。

## 已有结论统计

| 复核结论 | 数量 | 处理方式 |
| --- | ---: | --- |
| `keep` | 789 | 可保留在后续数据构建流程中 |
| `exclude` | 32 | 不进入最终训练、验证与测试清单 |
| `needs_expert` | 2 | 暂不进入最终训练、验证与测试清单，待矿物学专家进一步确认 |

## 需要补录的字段

当前队列中的 `reviewer` 和 `review_date` 为空；另有 3 条 `exclude` 记录未填写 `review_reason`。应由实际执行视觉复核的人员在原始 CSV 中补录以下信息：

1. `reviewer`：真实复核人姓名或可追溯代号；
2. `review_date`：实际复核日期，使用 `YYYY-MM-DD`；
3. `review_reason`：每条排除样本的具体原因，例如主体矿物不清、显微图、标签纸或标尺主导、混合矿物无法判定、明显失焦或过曝；
4. `expert_note`：对 `needs_expert` 样本记录待确认的矿物学问题及最终意见。

## 报告表述边界

在字段补录完成前，技术报告应表述为“建立并完成 823 张分层抽检队列的视觉判定，复核责任字段待归档补录”，而不应将脚本生成的初筛结果表述为人工复核证据。`scripts/review_fill.py` 如存在，仅可作为历史初筛工具，不得作为人工复核凭证。

## 归档建议

补录完成后，保留原始队列的只读备份，并在项目归档中同时保存：复核队列 CSV、接触表（contact sheet）、本说明、最终数据集排除清单及数据集版本号。
